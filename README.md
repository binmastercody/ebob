# Binventory eBob Guide

Open `index.html` in a browser (it opens the practice screen, see below). Everything runs from local files (file://), with no server and no internet needed. The only exceptions are the BinMaster support links, which open in a new tab.

## Opening screen (same pattern as the 3D Install, BinDisc and CNCR guides)
`index.html` opens the Binventory practice screen right away (`emulator.html`, free mode) with:
- a **welcome card** over the live Binventory screen: "Welcome to the Binventory Workstation Guide", Get Started, and the red Troubleshooting corner button
- a floating **"What would you like to do?"** box beside the Binventory window (same layout as the other guides: header with minimize, stacked buttons; in the eBob violet palette, 16px text that follows the text-size setting) with five choices: Install, upgrade or back up / Set up my site / Set up alarms and email / Readings and reports / Fix a problem. A choice opens its lessons in the same box, numbered by choice (2.1, 2.2 ...) so a tech can say "open 2.4". Numbers come from the order of the `CHOICES` lists, so adding a lesson at the end of a list keeps the others the same.
- a **copy-link icon** on every choice and lesson, so a tech can send a direct link. `emulator.html?do=<install|site|alerts|readings|trouble>` opens the box on that choice with no welcome card; `emulator.html?menu=1` opens the box with no welcome card (used by every lesson's Menu button and Back to menu).
- `app/quickmenu.js`, `app/quickmenu.css`: the welcome card and the box. The five choices and their lesson ids are the `CHOICES` list at the top of `quickmenu.js`.

## Files
- `lessons.html`: the full lesson list (was the home page; linked from the box as "Full lesson list"). Start here (five numbered steps with check marks and a Continue button), Find a task (seven task tiles that open to their lessons, plus a title search), Advanced (for IT staff) and Reference, with one Display settings button
- `app/home.js`, `app/home.css`: home page layout, task grouping and progress marks (lesson order and sections stay in `app/lessons.js`)
- `emulator.html`: the Binventory Workstation emulator with the guide layer (`?lesson=<id>`, or `?tutorial=db-read-only` / `pending-unknown-status`)
- `installer.html?lesson=<id>`: a working copy of the Binventory Workstation 1.0 Installer wizard, used by the Server/Host Install, Client Install, project import, Advanced (external SQL Server, add a site), upgrade lessons (`?mode=fresh|upgrade` to try it without a lesson). The upgrade lesson teaches the safe way: back up, choose Remove, restart, then do a normal install. It never uses the installer's Upgrade or Repair options. For a damaged install, remove, restart and install again
- `doc.html?lesson=<id>`: reading lessons (planning and PC requirements, installer troubleshooting)
- `app/installer-sim.js`, `app/installer-text.js`: the installer copy. Labels, messages and the license text are taken from the installer source.
- `app/lessons.js`: every lesson (sections, steps, targets, manual references)
- `app/guide.js`: lesson engine (pacing, input guard, Back, Next, progress)
- `app/display.js`: text size, pace, contrast and motion settings (localStorage `ebob-guide-display`)
- `app/guide.css`: all guide styling. The color palette lives in one place, the `:root` block at the top: `--c-*` custom properties for brand (BinMaster red `#C0202A`, charcoal `#282C38`), primary accent (violet `#5B3FA6`), neutrals, and semantic success, warning, error and info colors. `home.css` and the other pages only use these variables. The Workstation and installer replicas keep their own real-app colors and are not themed.
- `ebob-sim.js`: the emulator, generated by `tools/build.mjs` from the original. Changes: pacing hooks for the two built-in scenarios, and weight = volume x bulk density (or specific gravity x 62.428 lbs/cu ft) with unit conversion.

Each lesson has a Share button (in the lesson top bar, and beside every home lesson row) with Copy PNG, Download PNG and Email guide. This builds a picture walkthrough: a header with the BinMaster logo, the lesson title and Binventory Workstation 1.0, then each step's number, its text and a screenshot with the red circle on it. Long lessons are split into parts of about 10 steps. Copy PNG puts the first picture on the clipboard. If the browser will not allow copying, use Save picture (the pictures also go in your Downloads folder). Email guide opens your email app with a draft; it cannot attach the pictures, so paste with Ctrl+V. The encoded email stays under about 1800 characters.

Progress is saved in localStorage `ebob-guide-progress` (a lesson counts as done when it reaches its Lesson complete panel). Display settings are saved in `ebob-guide-display`.

## Adding a lesson
Add an `L.push({...})` in `app/lessons.js` and put its id in the `ORDER` list.
- A step is `{ title, msg, target, do: "click" | "type" | "select" | "check" | "uncheck" | "read" | "wait", value, until, reading }`.
- `reading` is a selector (or function) for a value the step talks about. The guide card is kept off it, as well as off the target, the red circle and the hand.
- An installer lesson adds `page: "installer"`.
- A reading lesson uses `kind: "doc"` and `doc: [{ title, html }]`.

## Testing (from /workspace/ebob/tools)
- `node walk.mjs <lesson ids...>`: clicks through lessons the way a person would
- `node verify.mjs`: checks the home page (Start here path, task tiles open and close, every lesson reachable, search, progress marks, Advanced, Reference, Display settings, layout at five screen sizes), pacing, font controls, scenarios, density and weight, reading lessons and links, and centering (card + window, home and reading pages) at 1024x576, 1280x720, 1440x900 and 1920x1080 at 100% and 150% text
- `node overlap.mjs`: walks every guided lesson and both scenarios at 1440x900 and 1280x720, at 100% and 150% text, and fails if the guide card covers a target, the red circle, the hand or a reading
- `node overlap-dynamic.mjs`: the same check after text size changes and window resizes
- `node shots-v2.mjs`, `node shots-v3.mjs`: screenshots in /workspace/ebob/shots
- `node center-probe.mjs <page> <step index>`: prints card and window margins at each screen size

## Lesson layout
- Setup install path: Before you install, Server/Host Install (the main PC with the database), Client Install (a workstation that connects to the Host PC by IP address and Connect), then the optional Server/Host Install with a project file.
- Advanced section (before Troubleshooting): Advanced: add a site, and Advanced: use an external SQL Server. Both use the installer's Advanced option (Workstation Client, eBob Services, SQL Server). With SQL Server unchecked the installer asks for IP Address from Host PC and tries the BINVENTORY instance, then EBOB, then the default instance. The practice Host PC is 192.168.1.20 and the practice external SQL Server is 192.168.1.30.

## Guide placement
When the card and the window fit side by side, the page reserves room left of the window (`html.eg-composed`, `--eg-dock-w`) so card + gap + window are centered as one unit, and the window is vertically centered below the top bar (`--eg-top`). This is decided per screen size and text size, not per step, so the window does not jump. The installer shrinks its zoom (not below 80%) to make room; the Workstation window narrows to no less than 960px. Otherwise the window is centered and the card floats over it.
The card docks beside the window when there is room, otherwise it moves to the first clear spot. If nothing is clear it shrinks to a bar. **Hide text** shrinks it by hand. It is re-placed on every step, dialog, resize and text size change.
